# 跨服务调用

1. 由提供能力的服务定义最小 Proto 契约，保持字段编号稳定并写中文注释；修改后使用仓库规定的 Proto 生成命令。
2. 提供方在自己的 RPC 服务中实现能力，并保留数据访问和业务规则在提供方内部。
3. 在 `native/internal/api/<service>/v1/contracts.go` 暴露最小 `API` 接口和 `Remote` 适配器，避免调用方依赖完整生成客户端细节。
4. 调用方在自己的组合根注入注册发现和 `transport.ClientPool`，通过服务发现获得实例；业务层不写死地址、不直接创建连接、不访问其他服务数据库。
5. 为请求设置明确的 context 超时和取消传播，定义错误映射、不可用时的行为、重试边界和幂等性。只有有证据时才增加重试。
6. 确保 HTTP、gRPC 和 Redis 相关链路的 trace context 正确传播，不在日志或 Span 中记录 Token、密码等敏感信息。

跨服务调用完成后同步 Proto 文档、架构文档、能力地图和相关测试。禁止用未声明的 Redis 频道或共享表绕过正式服务契约。

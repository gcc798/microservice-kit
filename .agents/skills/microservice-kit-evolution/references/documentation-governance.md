# 文档和能力地图治理

先更新事实来源，再更新引用方：

1. 架构变化写入 `native/docs/architecture.md`。
2. 配置、Proto、链路追踪变化分别写入对应专题文档。
3. 用户入口和命令变化更新根 `README.md` 与 `native/README.md`。
4. 新的永久开发规则更新 `AGENTS.md`，不要把一次性方案写成永久规则。
5. 先修改能力地图源 JSON，再按项目工具重新生成 HTML、图片和检查产物；不要手改生成的 HTML。
6. 删除已经失效的规划文档、旧架构名称、旧路径和死链接。

最终 `native/docs` 只保留当前仍有价值的架构和专题契约文档。不要保留重构计划、阶段性迁移说明或历史快照，除非用户明确要求归档。

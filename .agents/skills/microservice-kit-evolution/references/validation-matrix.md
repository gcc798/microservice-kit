# 验证矩阵

## 默认检查

在 `native` 执行：

- `go test ./...`
- `go vet ./...`
- `make verify`
- `git diff --check`

涉及 Proto 时，额外执行 Proto 生成和一致性检查；涉及能力地图时，验证源 JSON、生成产物和可视化检查。

## 真实服务验证

只有用户要求或改动影响运行拓扑时才操作 Docker。默认先停止并删除旧容器、保留数据卷，再用当前代码构建；不要未经明确授权删除数据库卷。

至少验证：

- 所有服务健康检查；
- Consul 注册实例数和服务状态；
- 目标横向扩展实例数；
- Gateway 到各后端的真实请求；
- 至少一条跨服务调用；
- 启停和优雅关闭；
- 日志与 trace 能关联到同一请求。

报告中区分“命令通过”“外部检查跳过”和“真实业务验证通过”，不能把容器启动成功等同于系统可用。
